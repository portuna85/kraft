# 02. 참고 분석과 디자인 방향

## 1. 참고 근거와 확인 범위

2026-09-10에 [와우 인벤 메인](https://wow.inven.co.kr/)의 공개 페이지 텍스트·HTML을 확인했다. 커뮤니티 종류별 탐색 그룹, 직업·서버별 게시판, 화제 글 모음, 정보 게시판과 더보기 연결이 존재한다. 이로부터 여러 게시판을 빠르게 탐색하고 제목 목록을 반복적으로 읽는 커뮤니티 구조를 참고한다.

메인에서 연결하는 [WoW 공개 스타일시트](https://www.inven.co.kr/wow/lib/style/dist/commu_style.css?v=e58df76717ce4837b22e3c1fdabaa905a)에서도 다음 선언을 확인했다.

| CSS 선택자 | 확인한 선언 | 해석 |
| --- | --- | --- |
| `#wowBody .commu-content>nav` | 배경 `#1e0f3c`, 글자 `#fff` | 탐색 영역의 짙은 색상 |
| `#wowBody .commu-left` | 배경 `#271e40`, 테두리 `#382e53` | 별도 왼쪽 영역의 색상 구분 |
| `#wowBody .commu-content>nav>ul>li>a:hover` | 글자 `#ffcf3e` | 탐색 상호작용에 강조색 사용 |

위 내용은 소스 확인 결과다. 스타일 선언이 최종 화면에서 어느 범위에 적용되는지, 다른 규칙에 덮어써지는지, 실제 모바일 전환이 어떻게 동작하는지는 화면 캡처 차단으로 확인하지 못했다. 아래 배치·토큰·크기는 **Kraft의 설계 제안**이다.

## 2. Kraft에 적용할 원칙

| 참고할 구조 | Kraft 적용 | 현재 기능과의 연결 |
| --- | --- | --- |
| 그룹화된 커뮤니티 탐색 | `커뮤니티`와 `계정`으로 메뉴 구분 | 전체 게시글, 글쓰기, 로그인·가입 또는 비밀번호 변경·로그아웃 |
| 제목 중심의 게시판 묶음 | 전체 게시글을 메인 콘텐츠로 배치 | 기존 페이지 조회와 목록 필드 활용 |
| 강조되는 영역 제목 | 화면 제목, 전체 게시글 수, 주 행동을 한 줄에 배치 | `totalElements`와 글쓰기 경로 |
| 짙은 탐색 영역과 강조색 | 짙은 Kraft 헤더, 인디고 활성 상태, 밝은 읽기 영역 | 기존 색상 체계 확장 |
| 보조 정보 영역 | 글쓰기 바로가기와 업로드·이용 안내 | 실제 기능의 정적 안내만 제공 |

현재 Kraft는 단일 게시글 목록을 제공하므로 메뉴를 늘리기 위해 존재하지 않는 게시판을 만들지 않는다. 게임 직업·서버 메뉴, 광고, 게임 뉴스, 순위, 인기글·추천 수는 기능 확장 시 따로 검토한다. 브랜드는 `Kraft`를 사용하고 인벤·WoW 로고, 일러스트와 콘텐츠를 제품 자산으로 복제하지 않는다.

## 3. 목표 인상과 우선순위

**읽기 쉬운 커뮤니티 게시판**을 목표로 한다. 첫 화면에서 서비스 이름, 현재 게시판, 최신 등록 순 목록, 글쓰기 진입을 파악할 수 있어야 한다.

- 정보 우선순위: 제목 → 작성자와 시간 → 글 번호 → 보조 안내.
- 본문을 흰색 표면에 배치하고, 헤더는 짙게 하여 탐색과 읽기 영역을 구분한다.
- 기존 인디고를 주요 행동과 활성 상태에 사용한다. 금색 계열은 이용 안내처럼 제한된 보조 표시에 사용한다.
- 표와 목록은 구분선으로 묶고, 카드와 그림자는 계정·안내 영역에서 절제해 사용한다.
- 첫 구현은 텍스트와 실제 첨부 이미지로 구성한다. 별도 대형 배너나 장식용 이미지는 요구하지 않는다.

## 4. 색상 토큰 제안

기존 `--kraft-*` 네이밍을 확장한다. 아래 표는 최종 CSS 구현을 위한 제안이며 현재 코드에 반영된 값은 아니다.

| 토큰 | 값 | 사용 |
| --- | --- | --- |
| `--kraft-primary` | `#4f46e5` | 주요 버튼, 현재 페이지, 포커스 |
| `--kraft-primary-dark` | `#4338ca` | 주요 버튼 hover·active |
| `--kraft-header` | `#192335` | 헤더·브랜드 영역 |
| `--kraft-bg` | `#f3f4f6` | 전체 배경 |
| `--kraft-surface` | `#ffffff` | 게시판·폼 표면 |
| `--kraft-surface-subtle` | `#f8fafc` | 목록 헤더·보조 영역 |
| `--kraft-text` | `#1f2937` | 본문·제목 |
| `--kraft-text-muted` | `#5f6b7a` | 작성자·시간·설명 |
| `--kraft-border` | `#d5dae3` | 장식용 구분선 |
| `--kraft-control-border` | `#768397` | 입력 컨트롤 경계 |
| `--kraft-accent-text` | `#80601e` | 안내 강조 글자 |
| `--kraft-accent-bg` | `#fff7e0` | 안내 배경 |
| `--kraft-success` | `#166534` | 성공 메시지 |
| `--kraft-danger` | `#b42318` | 오류·삭제 행동 |

불투명 sRGB 값으로 계산한 대비는 본문/흰색 14.68:1, 보조 글자/흰색 5.43:1, 흰 글자/인디고 6.29:1, 흰 글자/헤더 15.75:1, 안내 글자/안내 배경 5.44:1이다. 입력 경계/흰색은 3.84:1이다. 실제 구현에서는 hover, disabled, 투명도, 배경 조합까지 다시 검사한다.

일반 텍스트 대비 목표는 최소 4.5:1이다. 큰 텍스트의 예외에 의존해 본문을 배치하지 않는다. 기준: [W3C WCAG 2.2 — Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## 5. 서체·간격·형태

| 항목 | 제안 기준 |
| --- | --- |
| 폰트 | 기존 시스템 한글 폰트 스택 유지. `Pretendard`가 설치되지 않은 환경도 검증 |
| 기본 본문 | 16px, 행간 1.6 |
| 게시글 읽기 본문 | 16px, 행간 1.75, 공백·줄바꿈 보존 |
| 목록 제목 | 모바일 16px, 태블릿 이상 15px, 두께 500 |
| 메타 정보 | 13~14px, 행간 1.5 |
| 페이지 제목 | 모바일 24px, 데스크톱 28px, 두께 700 |
| 섹션 제목 | 18~20px, 두께 700 |
| 간격 단위 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 표면 모서리 | 8px, 버튼·입력은 6px |
| 입력·버튼 높이 | 기본 44px 이상. 작은 시각 요소도 터치 영역은 44 × 44px 이상 |
| 본문 컨테이너 | 최대 1280px, 작은 화면 좌우 16px, 768px 이상 좌우 24px |
| 그림자 | 안내 카드에는 약한 그림자, 목록은 테두리와 행 구분선 중심 |
| 상태 전환 | 120~180ms, 움직임 축소 설정 시 제거 또는 최소화 |

44px 터치 영역은 Kraft의 사용성 목표다. 이 수치를 WCAG AA의 일률적인 최소 요구라고 표현하지 않는다.

## 6. 컴포넌트 방향

| 컴포넌트 | 시각·동작 기준 |
| --- | --- |
| 공통 헤더 | 텍스트 브랜드, 현재 위치, 계정 진입. 긴 이메일이 본문 폭을 밀지 않도록 계정 메뉴 안에서 줄바꿈 |
| 탐색 | `커뮤니티`, `계정` 제목과 링크 목록. 현재 링크는 배경·강조선·`aria-current`로 표현 |
| 게시판 제목 영역 | `전체 게시글`, 총 개수, 글쓰기 버튼. 제목 아래 설명은 한 문장 |
| 게시글 목록 | 넓은 화면은 열 정렬, 작은 화면은 제목 아래 메타 정보. 하나의 데이터 집합과 링크 사용 |
| 버튼 | 주요 행동은 인디고, 보조 행동은 테두리, 삭제는 위험 색상. 아이콘 없이도 의미가 드러나는 한국어 라벨 |
| 폼 | 라벨·설명·입력·오류 순서. 입력값을 지우지 않고 오류 위치 안내 |
| 댓글 | 작성자·작성 시각·본문·관리 행동의 반복 구조. 작성 폼은 목록 뒤에 배치 |
| 피드백 | 결과를 담는 고정 메시지와 간단한 토스트. 중요한 오류는 3초 뒤 사라지는 토스트에만 의존하지 않음 |

## 7. 범위 결정

이번 설계는 기존 화면과 API를 연결하는 반응형 전환이다. React·Next.js 같은 별도 프론트엔드 프레임워크, 신규 빌드 체인, Bootstrap 버전 교체는 필수 조건이 아니다.

실제 기능을 가진 탐색 항목과 버튼만 제공한다. 검색·분류·통계·프로필을 추가하려면 데이터와 API 요구사항부터 별도 정의한다. 이미지 교체·삭제, 이메일 인증 재발송, 비밀번호 찾기 역시 현재 제공된 기능으로 표시하지 않는다.
