# VoiceOver / NVDA 수동 점검 체크리스트 — KRAFT 리디자인 P0

대상: kraft.io.kr (배포됨). 자동화 테스트(axe, keyboard-flows.spec.ts, dropdown-menu.test.tsx 등)는
이미 CI에서 통과했다 — 이 체크리스트는 **자동화가 못 잡는 것**(실제 음성 출력, 랜드마크 탐색,
발표 타이밍)에 집중한다.

## 준비

- **VoiceOver**: macOS, Safari 또는 Chrome. `Cmd+F5`로 켜고 `Ctrl+Option`(VO 키)+화살표로 탐색.
- **NVDA**: Windows, Chrome 또는 Firefox 권장(Edge도 가능). 무료 다운로드 후 실행.
- 두 스크린리더 모두 **화면을 보지 않고** 점검하는 것이 이상적이다 — 화면을 보면서 "들리니까 됐다"고
  판단하면 실제로 이해 가능한 순서로 들리는지 놓친다.
- 데스크톱 폭(≥1152px)과 모바일 폭(≤767px) 둘 다 최소 1회씩 점검한다 — 헤더 내비게이션 구조가
  폭에 따라 다르다(데스크톱: 인사이트 드롭다운 / 모바일: 하단 탭바).

---

## 1. 전역 — 스킵 링크·랜드마크

- [ ] 페이지 로드 직후 첫 Tab에서 "본문으로 건너뛰기" 링크가 들리는가. 활성화 시 실제로 `<main>`
      시작 지점으로 포커스가 이동하는가(랜드마크 이름 없이 "메인"만 들려도 정상).
- [ ] 랜드마크 탐색(VoiceOver: VO+U → Landmarks, NVDA: `D` 키)으로 이동했을 때 다음이 모두
      구분되어 들리는가: banner(헤더), navigation "주요 메뉴", main, contentinfo(푸터).
- [ ] 모바일 폭에서는 추가로 navigation "바로가기"(하단 탭바)가 별도 랜드마크로 들리는가.

## 2. 헤더 — 4대축 내비게이션 + 인사이트 드롭다운 (데스크톱 폭)

- [ ] "주요 메뉴" 내비게이션에 진입하면 순서대로 "번호 추천", "추천 이력", "내 조합 진단",
      "인사이트"(버튼), "커뮤니티"가 들리는가.
- [ ] "인사이트" 항목이 **링크가 아니라 버튼**으로 들리고, "접힘"/"collapsed" 상태가 함께
      발표되는가(`aria-expanded="false"` → "collapsed" 또는 "축소됨").
- [ ] "인사이트" 버튼에서 Enter/Space로 열면 "확장됨"으로 상태가 바뀌어 들리고, 메뉴가 열렸다는
      사실과 항목 수가 발표되는가(`role="menu"` + `aria-label="인사이트 메뉴"`).
- [ ] 메뉴가 열린 상태에서 화살표 아래/위로 항목 간 이동 시 각 항목이 "메뉴 항목, 데이터 개요"
      처럼 role과 이름이 함께 들리는가. 항목: 데이터 개요·번호별 출현·당첨 패턴·함께 나온 번호·
      데이터 출처·방법론.
- [ ] Escape로 닫으면 포커스가 "인사이트" 트리거로 돌아오고, 트리거 상태가 다시
      "collapsed"로 들리는가.
- [ ] 현재 페이지가 인사이트 하위 라우트(예: `/frequency`)일 때, 트리거 자체가 시각적으로는
      강조되지만(`data-active`) 스크린리더로는 "현재 페이지"라는 과도한 발표 없이 자연스러운가
      (버그는 아니지만, 트리거가 현재 상태를 전혀 알리지 않는 것이 아쉬운 지점이라면 기록해 둔다 —
      이번 P0 범위에서 의도적으로 `aria-current`를 트리거에 붙이지 않았다).
- [ ] "보관함" 링크(유틸리티 영역, 테마·로그인 옆)가 주요 메뉴와 분리된 그룹으로 들리는가
      (혼동해서 "주요 메뉴의 6번째 항목"처럼 들리면 문제).

## 3. 헤더 — 모바일 하단 탭바 (모바일 폭)

- [ ] "바로가기" 내비게이션에서 홈·추천·데이터·커뮤니티·보관함 5개 탭이 순서대로 들리는가.
- [ ] 현재 페이지에 해당하는 탭이 "현재 페이지"로 발표되는가(`aria-current="page"`).
- [ ] `/frequency`·`/stats`·`/companion`·`/analysis`에 있을 때 "데이터" 탭이 현재로 발표되는가
      (alias 처리 — 시각적으로는 이미 확인됨, 음성으로도 같은 판정인지 확인).

## 4. 홈 — 3단계 안내 · 인사이트 미리보기

- [ ] 히어로의 `<h1>`이 "최신회차 1238회, 2026년 8월 22일 추첨" 형태로 자연스럽게 들리는가
      (숫자만 뚝 끊겨 들리지 않는지).
- [ ] "번호 추천받기", "내 조합 진단하기" 두 CTA가 버튼처럼 보이지만 실제로는 **링크**로 발표되는가
      (`LinkButton`은 `<a>`이므로 "링크, 번호 추천받기"가 정상 — 사용자가 "이동"과 "실행"을 구분할
      수 있어야 한다).
- [ ] "이렇게 시작하세요" 섹션의 3단계가 순서 목록(`<ol>`)처럼 "목록 1/3", "목록 2/3", "목록 3/3"
      또는 이에 준하는 순서 정보와 함께 들리는가. 각 단계 제목(전략 선택/번호 고정·제외/생성 및
      저장)과 설명이 헤딩 레벨(h3) 구분과 함께 들리는가.
- [ ] "데이터로 살펴보기" 섹션의 3개 타일이 각각 하나의 링크로 들리고, 링크 이름에 라벨+설명
      텍스트가 모두 포함되는가(예: "번호별 출현 출현 빈도 보기" — 링크 전체가 하나의 접근 이름).

## 5. 추천 생성 플로우 (`/recommend`)

- [ ] 페이지 진입 시 `<h1>` "번호 추천"이 먼저 들리는가.
- [ ] 확률 고지 영역이 `status`(경고 톤이라도 alert 아님, 작업 방해 없이) 역할로 들리고,
      "추천 번호에 대해 알아두세요" 제목 뒤 확률 문구가 이어지는가.
- [ ] "자세히 보기" 버튼이 `aria-expanded="false"`로 들리고, 활성화 후 "간단히 보기"로 라벨이
      바뀌면서 `aria-expanded="true"`로 상태가 갱신되는가. 펼쳐진 본문(구매 책임 문구)이
      실제로 다음 탐색 순서에 나타나는가.
- [ ] "어떻게 고를까요" 전략 선택이 라디오 그룹으로 들리는가 — `fieldset`의 sr-only
      `legend`("추천 전략")가 그룹 이름으로 발표되는지, 각 옵션이 "라디오 버튼, 균형 잡힌 조합,
      선택됨/안 됨"처럼 이름+역할+상태가 함께 들리는지.
- [ ] "조합 개수" 입력 필드의 라벨("조합 개수 (1~10)")이 입력창과 정확히 연결되어 들리는가.
- [ ] "고정 번호"/"제외 번호" 세그먼트 컨트롤이 라디오 그룹으로 들리고 좌우 화살표로 전환되며,
      전환 시 활성 옵션이 상태 변경으로 들리는가.
- [ ] 번호 그리드에서 화살표로 셀 간 이동 시(roving tabindex) 각 셀이 "1번" 같은 이름과 함께
      들리고, 선택 후에는 이름이 "1번, 고정됨"처럼 상태 포함 형태로 바뀌는가(색상만으로 상태를
      구분하지 않는다는 계약의 청각적 확인).
- [ ] 번호를 고정/제외할 때마다 "고정 X/5", "제외 Y" 요약이 `aria-live="polite"`로 **자동
      발표**되는가(포커스가 그 텍스트로 이동하지 않아도 들려야 한다). 이번 리디자인에서 이 요약이
      배지(Badge) 두 개로 나뉘었는데, 두 배지 텍스트가 하나의 발표로 자연스럽게 이어 들리는지,
      혹은 따로 끊겨 들려도 의미가 통하는지 확인한다.
- [ ] 고정 5개를 채운 뒤 6번째를 시도하면 "X번은 선택할 수 없습니다..." 문구가 `status`로
      즉시 발표되는가(매번 같은 번호를 다시 시도해도 재발표되는지 — 문구가 안 바뀌면 스크린리더가
      "이미 읽은 텍스트"로 취급해 조용할 수 있다. 이번 구현은 거부된 번호 자체를 상태로 남겨
      매번 문구가 갱신되므로 재발표되어야 정상이다).
- [ ] 하단 sticky 액션바("조합 만들기")가 스크린리더 탐색 순서에서 **부자연스러운 위치에 끼어들지
      않는가** — DOM 순서상 "선택 모두 해제" 버튼 다음, 결과 섹션 이전이 맞다. `position: sticky`가
      시각적 위치만 바꾸고 읽기 순서에 영향을 주지 않는지 확인(영향을 주면 버그).
- [ ] "조합 만들기" 실행 후 포커스가 "추천 조합" 헤딩으로 자동 이동하는가(`tabIndex={-1}` +
      `focus()` — 클릭으로는 못 가지만 스크립트로는 가야 한다). 그 직후 "N개 조합이
      생성되었습니다"가 sr-only `status`로 발표되는가.
- [ ] 조건(고정/제외)을 바꾼 뒤 다시 만들지 않으면 "조건이 바뀌었습니다 · 다시 만들기"가
      `status`로 발표되는가.

## 6. 추천 결과 — 칩·자세히·저장 액션

- [ ] 각 결과 행이 "추천 1"이라는 라벨과 함께 로또 볼 6개가 순서대로 들리는가(공만 듣고 순서를
      알 수 없으면 문제).
- [ ] 설명 칩(홀짝 균형·고저 균형·합계 적정·연속 번호 적음·구간 분산)이 각각 별개 항목으로
      들리는가, 아니면 뭉쳐서 한 덩어리로 들리는가 — Badge는 `<span>`이라 개별 항목 경계가
      스크린리더마다 다르게 처리될 수 있다. 최소한 텍스트 전체가 빠짐없이 들려야 한다.
- [ ] "자세히" 버튼이 `aria-expanded`/`aria-controls`로 펼침 상태를 알리고, 펼친 뒤 전체 문장
      목록(홀짝이 고르게 섞였습니다 등)이 순서대로 들리는가.
- [ ] "보관함에 저장" 버튼 실행 후 "저장했습니다."/"이미 저장한 조합입니다." 배지가 `status`로
      발표되는가 — 포커스가 버튼에 남아 있는 상태에서 발표만 되어야 한다(포커스 이동 없이).
- [ ] "이 조합으로 진단하기" 링크가 "링크, 이 조합으로 진단하기"로 들리고, 활성화 시 `/analysis`
      로 이동해 그 페이지 진입이 자연스럽게 발표되는가(새 `<h1>` "내 조합 진단"이 들리는지).
- [ ] "전체 저장" 버튼(결과 헤더 영역)이 "추천 이력 보기" 링크와 혼동 없이 별개 컨트롤로
      들리는가.

## 7. 교차 점검 — 흔한 회귀 패턴

- [ ] 어떤 상태 변화도 **포커스를 빼앗지 않고** 발표만 되는지(칩 저장, 거부 번호, 낡음 알림 등) —
      의도치 않게 포커스가 튀면 사용자가 방금 어디 있었는지 잃는다.
- [ ] 다크 모드 전환 버튼이 "라이트 모드로 전환"/"다크 모드로 전환"처럼 **다음 동작**을 이름으로
      갖는가(현재 상태가 아니라).
- [ ] 페이지 전환(예: 홈 → 추천) 시 새 `<h1>`이 합리적인 시점에 발표되는가 — Next.js 클라이언트
      네비게이션 후 포커스가 완전히 사라지거나 body로 리셋되어 스크린리더가 아무 안내 없이
      "빈 페이지"처럼 느껴지면 기록한다(이번 리디자인 범위 밖의 프레임워크 차원 이슈일 수 있으나,
      발견되면 별도 항목으로 분리해 보고한다).

## 결과 기록 방법

각 항목을 Pass/Fail/N/A로 표시하고, Fail 항목은 다음을 함께 남긴다:
1. 브라우저/스크린리더 조합(예: Chrome + NVDA 2024.4)
2. 실제로 들린 내용(가능하면 그대로 인용)
3. 기대했던 내용
4. 재현 경로(페이지 → 조작 순서)
